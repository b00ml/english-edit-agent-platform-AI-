- **优点**：技术栈选择极务实 — FastAPI+LangGraph+Celery+React+Docker 全是成熟生态，架构文档一出来就能开工，没有「调研/选型周」。

## 5. 关键问题与根因分析

### 问题 1：Docker 构建中才暴露前端类型错误（OPT-011）

**现象**：前端 SamplesPage.tsx 的 `s.meta?.qc_score` 类型为 unknown，不能直接当 ReactNode，本机未跑 tsc，直到 Docker build 时才报错、阻塞镜像构建。

**根因**：
- 人：本机未安装 Node / npm，tsc 作为开发前门禁缺席。
- 流程：没有"前端 tsc → 后端 pytest → 再提变更"的标准开发 SOP。
- 工具：前端 package.json 无 pre-commit/hook，靠人为记忆执行。

**影响**：一次 frontend 构建失败；需要回溯修复。**影响程度：低，但可重复发生（系统性风险）。**

**问题类型**：系统性（流程 + 工具）
**是否下次重复发生**：是，除非加门禁。

---

### 问题 2：Alembic 迁移父子关系错误（迁移 g6b7c8d9e0f1 初始指错 down_revision）

**现象**：手动创建迁移时 down_revision 误写为 f5a6b7c8d9e0，实际应为 b1c2d3e4f5a6，导致 2 个子版本同时指向同一父，`alembic upgrade head` 报 "Multiple heads"。

**根因**：
- 流程：迁移文件采用"复制旧迁移 + 手动改 ID"模式，手工维护父子链，没有用 `alembic revision --autogenerate -m "xxx"` 自动生成 head 指针。
- 工具：没有迁移检查脚本（如 `alembic check` / `alembic current` 作为上线前检查）。

**影响**：迁移执行失败，需改 ID 后重建镜像重试。**影响程度：低 + 可重复发生。**

**问题类型**：系统性（流程 + 工具）

---

### 问题 3：结构化输出边界 Bug（OPT-006 list 崩溃 + OPT-007 数组包装）

**现象 1**：模型偶发返回顶层 JSON 数组而非对象 → `_normalize_flat` 对 list 调 `.keys()` → AttributeError → 逃逸重试失败路径 → 整题崩溃。

**现象 2**：模型返回 `{"questions":[{...}]}` 数组包装 → `_normalize_flat` 未解包 → Pydantic 校验失败并重试 3 次全挂。

**根因**：
- 人：Outlines SDK 选型替换为 Pydantic v2 校验时，没有做"Schema 形状全排列"的边界测试 —— 只测了 happy path 的对象形状，没测 list 顶层 / 嵌套包装。
- 规则：没有"结构化输出引擎必须包含哪些回归用例"的 Checklist。Schema 构造函数是递归的，但输入归一化不是。
- 流程：没有把「云端 API 实际返回的所有奇怪形状」提前列成测试集。

**影响**：
- OPT-006：批量生成任务 item 4 直接崩溃（重试失效），端到端 4 题任务部分成功。
- OPT-007：数组包装被误认为是连接超时挂起 10 分钟的根因，排查了一段时间才发现是形状问题。

**问题类型**：系统性（规则缺口 + 测试集缺口）
**是否下次重复发生**：每次新增题型/新 Schema 都可能出现新形状逃逸。

---

### 问题 4：TraceLog 字段多次追加迁移（c2d8→d3e9→a7b8 共 4 次 trace 相关迁移）

**现象**：初始 TraceLog 只有 model/cost/latency；后来才补 task_id/template_id（成本聚合用），再补 stage/prompt_tokens/completion_tokens（深度成本用）。每次都要新增一次迁移 + 改写入点 + 改接口。

**根因**：
- 流程：建表前没按 PRD §15（数据指标）+ §14（成本核算）逐项列出 TraceLog 需要的字段。
- 数据：可观测性的"最小字段集"没有一次性确定，随 KPI / 成本功能开发才倒推需要什么字段。

**影响**：
- 4 次迁移 vs 理想 1 次；每次迁移都有 down_revision 出错风险。
- 旧 trace 记录缺少 task_id/stage/token，无法做历史数据完整回溯（时间断层）。

**问题类型**：系统性（设计）。

### 问题 5：Langfuse upstream latest 升级导致服务崩溃

**现象**：RAG 上传上线后重启 docker，langfuse 因 latest tag 从 v2→v3 不兼容升级而崩溃。

**根因**：
- 规则：docker-compose.yml 中 langfuse 用 `latest` 标签，没有锁定版本。
- 工具：`docker compose up -d` 不 `--pull always` 可能没事，但一拉 latest 就变版本。

**影响**：langfuse 服务挂掉（可选接入，非致命核心链路）。修复方式是 pin 到 v2。**可重复发生在任何未锁版本的 image 上。**

**问题类型**：系统性（流程 + 规则）

## 10. 可沉淀资产（本版本新增的方法）

### 10.1 Checklist：开发前门禁（对应 S3/A1）

每次准备提交代码前，必须：

- [ ] `cd backend && python -m pytest -q -o addopts=""` → 退出 0，所有单测通过
- [ ] `cd frontend && npx tsc --noEmit` → 退出 0，无类型错误
- [ ] 如本次有 DB schema 变化：`alembic upgrade head` 成功（无 multiple heads）
- [ ] 如本次有 API 变化：README 核心接口表 + client.ts + types.ts 三处同步

### 10.2 Checklist：TraceLog 建表字段（对应 S4/A3）

建/扩展 TraceLog 前，逐项打勾：

- [ ] 成本聚合必要维度：template_id / task_id / model_name
- [ ] token 细分：prompt_tokens / completion_tokens
- [ ] 阶段标签：stage（generate / qc / revise / embedding …）
- [ ] 回放必要信息：trace_id / input_snapshot / output_snapshot / latency_ms / cost
- [ ] 预留扩展：tenant_id / meta JSONB
- [ ] 必要索引：trace_id / task_id / template_id / stage

### 10.3 Checklist：结构化输出形状回归（对应 问题 3/A5）

每次修改 `structured_output.py` 或新增题型模板，必须补以下形状回归：

- [ ] 正常对象（happy path）
- [ ] 顶层是数组而非对象 `[{...}]`
- [ ] 数组包装 `{"questions":[{...}]}` 或 `{"data":[...]}`
- [ ] 空对象 `{}`
- [ ] `null`
- [ ] 纯 JSON 字符串（不是 dict）

### 10.4 SOP：Alembic 迁移自动生成法（对应 S1/A2）

```bash
cd backend
# 1. 修改 models.py 中的 SQLAlchemy 模型
# 2. 自动生成迁移（自动填好正确的 down_revision）
alembic revision --autogenerate -m "add xxx table / add yyy column"
# 3. 打开生成的新文件检查 upgrade/downgrade，必要时手工调整
# 4. 本地跑一遍再提交
alembic upgrade head && alembic downgrade -1 && alembic upgrade head
```

### 10.5 SOP：Docker Compose 上线冒烟（对应 A7）

```bash
cd /path/to/english-edit
docker compose -f deploy/docker-compose.yml up -d --build
# 跑冒烟脚本
bash deploy/smoke_test.sh
# 期望输出：All smoke tests passed (exit 0)
```

### 10.6 规则：docker-compose image 不得使用 `:latest`（对应 S2/A4）

修改 `deploy/docker-compose.yml` 的审查规则：所有 `image:` 字段禁止出现 `latest`，必须锁定主版本号（如 `postgres:16-alpine` / `langfuse:2` / `redis:7`）。这是本次 5 个系统性问题中最容易用 grep 一条命令验证的。

```bash
grep "image:" deploy/docker-compose.yml  # 不应出现任何 ":latest"
```
