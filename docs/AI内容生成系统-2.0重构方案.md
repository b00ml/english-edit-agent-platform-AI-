# 英语教研 AI 内容生成系统 2.0 重构方案

> 基于去年 0-1 落地经验与当前技术演进，重新设计一个更贴合时代的产品。
> 定位：从「单点生成工具」升级为「AI 原生的教研内容生产平台」。

---

## 一、项目回顾与复盘

| 维度 | 1.0 做法 | 结果 |
| --- | --- | --- |
| 平台 | Dify + 推理 API | 生产周期从数周压缩到数小时，支撑 5 万+ 内容 |
| 模型 | Llama3 + LoRA | 推理成本同比降 20% |
| 批处理 | Python 脚本 + csv + 动态 API | 单次运行时间缩短 25% |
| Prompt | ROLE-PROFILE-INPUT-OUTPUT-WORKFLOW | 复杂 JSON 结构化符合率 80% → 99%+ |

**1.0 的核心资产**：结构化 Prompt 框架、题型生产方法论、成本优化经验。
**1.0 的短板**：以「脚本 + Prompt」为主，缺少质量闭环、可观测性、规模化协作能力，本质是"半自动化工具链"而非"产品"。

---

## 二、技术演进带来的重构机会

| 演进方向 | 对内容生成系统的意义 |
| --- | --- |
| **Agent / Workflow 成熟** | 从单次生成升级为「选题→出题→质检→改版→入库」的多步自动编排 |
| **结构化输出规范化** | JSON Schema + Function Calling / 约束解码，比 1.0 靠 Prompt 硬掰更可靠 |
| **RAG / 知识库成熟** | 模型可引用教材、课标、真题库，内容有据可依 |
| **Eval / LLM-as-judge** | 建立自动质检打分，替代人工抽检，形成质量闭环 |
| **可观测性（Langfuse 等）** | 每个生成样本可追踪、可复盘、可回放 |
| **推理成本持续下降 + 国产模型成熟** | Qwen、DeepSeek、GLM 系列性价比远超 1.0 时代 |
| **多模态** | 可覆盖听力、口语、图文阅读等题型（1.0 主要是文本） |

---

## 三、产品定位

**一句话**：面向英语教研团队的「AI 原生内容生产线」，让"选题 → 生成 → 质检 → 发布"全流程可编排、可评估、可持续优化。

**核心差异点（相对 1.0 与竞品）**：

1. **质量有闭环**：自动质检 + 人工抽检，形成数据回流，持续微调。
2. **题型可扩展**：题型以「配置化模板」接入，新增题型不改代码。
3. **可观测可复盘**：每次生成都有 trace，有问题可追根因。
4. **成本透明**：按模板、按模型、按题型核算成本，支撑规模化。

## 五、关键技术设计

### 5.1 题型模板化（核心可扩展性）

1.0 的 Prompt 框架升级为「题型 Schema」配置：

```yaml
# 题型模板示例：单选题
题型: 单项选择
输入:
  - 知识点: string
  - 难度: enum[易,中,难]
  - 数量: int
输出_schema:            # JSON Schema，驱动结构化输出
  type: object
  required: [stem, options, answer, explanation]
  properties:
    stem: {type: string, desc: 题干}
    options:
      type: array
      items: {type: string}
      minItems: 4, maxItems: 4
    answer: {type: string, enum: [A, B, C, D]}
quality_rules:          # 质检规则（LLM-judge 打分维度）
  - 知识点匹配
  - 难度匹配
  - 选项干扰性
  - 无歧义
```

> 新增题型 = 新增一个 YAML 模板，无需改代码。

### 5.2 结构化输出

- 用 **JSON Schema + Function Calling**（或约束解码 Outlines/grammar）替代纯指令硬掰，符合率从 99% 进一步逼近 100%，且天然可校验。
- 输出后做 Schema 校验，失败走「重试路由」而非放弃。

### 5.3 质量闭环（Eval）

- **自动质检**：LLM-as-judge 按 `quality_rules` 打分，低分自动进入改版流程。
- **人工抽检**：抽样标注，回传评估结果。
- **数据回流**：高质量样本沉淀为微调 / few-shot 语料，持续提升。

### 5.4 模型选型与路由（2026 视角）

- 基座候选：**Qwen2.5 / DeepSeek-V3 / GLM-4 / Llama3.3**，按性价比与生成质量评测。
- 路由策略：简单题型走轻量模型，复杂/高价值题型走高配模型，成本差可达数倍。
- 微调：QLoRA / LoRA，配合 DPO 用质检数据优化，替代 1.0 单一 LoRA。
- 推理部署：vLLM（连续批处理 + PagedAttention），进一步压低成本。

### 5.5 批处理 → 任务编排

- 1.0 的 Python 脚本升级为**异步任务队列 + 断点续跑 + 并发控制**，解决超时、环境依赖问题，并支持失败重试与任务级别监控。

### 5.6 可观测性

- 全链路 Trace（Langfuse / 自建），记录：prompt 版本、模型、输入输出、质检分、耗时、成本。
- 支持「回放一次生成」，定位质量问题根因。

## 六、落地路线（分阶段）

| 阶段 | 目标 | 关键交付 |
| --- | --- | --- |
| **P0 验证** | 打通最小闭环 | 2-3 类题型模板化 + 自动质检 + 入库 |
| **P1 骨架** | 可编排生产线 | 任务队列 + 题型 Schema 扩展 + RAG 接入 |
| **P2 质量** | 质量闭环 | LLM-judge 质检 + 数据回流 + 微调 |
| **P3 平台** | 产品化 | 前端工作台 + 可观测性 + 成本核算 + 多端发布 |

---

## 七、成本与风险

- **成本**：模型路由 + vLLM 批处理，较 1.0 有望进一步下降；Eval 增加一定 token 开销，需评估投入产出。
- **风险**：
  - 质检标准主观 → 用「规则 + LLM-judge + 人工」三层，逐步校准。
  - 题型扩展失控 → 用 Schema 模板约束 + 版本管理。
  - 数据质量 → 入库前必须过质检，阻止劣质内容污染内容库。

## 八、与 1.0 对比总结

| 能力 | 1.0 | 2.0 |
| --- | --- | --- |
| 生产方式 | 脚本 + Prompt | Agent 编排 + 模板化 |
| 结构化 | Prompt 硬掰 | JSON Schema + Function Call |
| 质量 | 人工抽检 | 自动质检 + 数据回流闭环 |
| 扩展题型 | 改代码/Prompt | 加 Schema 模板 |
| 可观测 | 无 | 全链路 Trace |
| 成本 | 单模型 | 模型路由 + 批处理优化 |
| 知识依据 | 弱 | RAG 接入教材/题库 |
