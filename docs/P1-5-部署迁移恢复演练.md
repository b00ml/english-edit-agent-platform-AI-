# P1-5 部署、迁移和恢复演练

## 目标与边界

本演练验证四件事：Langfuse 独立数据库能初始化；Alembic 迁移只有单一 head 且可在启动前预检；PostgreSQL 备份可恢复到独立目标库；LangGraph checkpoint 与任务 outbox 能在故障后重放。恢复操作不覆盖源数据库。

## 1. 初始化

从仓库根目录启动：

```powershell
docker compose -f deploy/docker-compose.yml up -d postgres redis
```

Postgres 数据卷首次初始化时执行 `deploy/postgres-init/01-create-langfuse-db.sql`，创建 `langfuse` 数据库。校验：

```powershell
docker exec english-edit-postgres psql -U postgres -lqt
```

输出必须同时包含 `english_edit` 和 `langfuse`。已有数据卷不会自动执行 init 脚本，需由 DBA 显式创建数据库后再启动 Langfuse。

## 2. 迁移预检与启动

```powershell
docker compose -f deploy/docker-compose.yml run --rm backend python scripts/migration_precheck.py
docker compose -f deploy/docker-compose.yml run --rm backend alembic upgrade head
```

预检检查数据库 `SELECT 1`、当前 revision 和脚本目录 heads；heads 不是一个时退出码为 `2`，禁止继续迁移。数据库不可连接、迁移表读取失败或其他预检异常时退出码为 `1`。当前脚本在 Alembic 包不可导入时使用 AST 静态解析迁移 head，但仍要求真实数据库连接通过。

## 3. 备份与恢复

备份源库：

```powershell
./backend/scripts/backup_restore.ps1 -Mode backup `
  -DatabaseUrl 'postgresql://postgres:postgres@localhost:5432/english_edit' `
  -File '.\backup\english_edit.dump'
```

先创建独立目标库 `english_edit_restore`，再恢复：

```powershell
./backend/scripts/backup_restore.ps1 -Mode restore `
  -DatabaseUrl 'postgresql://postgres:postgres@localhost:5432/english_edit' `
  -TargetDatabaseUrl 'postgresql://postgres:postgres@localhost:5432/english_edit_restore' `
  -File '.\backup\english_edit.dump'
```

脚本拒绝缺少目标库、目标等于源库、备份文件不存在的情况，并且不使用 `--clean/--create`，避免恢复流程覆盖已有对象。

## 4. checkpoint 与 outbox 重放

### 4.1 PostgresSaver 跨连接 checkpoint 演练

backend 镜像包含一个不调用 LLM 的最小 interrupt 图，可用两个独立容器命令模拟 worker/process 重启：

```powershell
$threadId = "recovery-drill:$(New-Guid)"
docker compose -f deploy/docker-compose.yml run --rm backend `
  python scripts/recovery_drill.py --phase checkpoint-start --thread-id $threadId

# 关闭上一个容器后，以全新进程/数据库连接恢复同一 thread
docker compose -f deploy/docker-compose.yml run --rm backend `
  python scripts/recovery_drill.py --phase checkpoint-resume --thread-id $threadId
```

第二条命令必须输出 `status=approved counter=1`；这证明 interrupt 前的节点只执行一次，状态从 PostgreSQL checkpoint 读取。

### 4.2 Outbox dead/replay/relay 演练

```powershell
docker compose -f deploy/docker-compose.yml run --rm backend `
  python scripts/recovery_drill.py --phase outbox
```

脚本创建带合成失败原因的临时 dead 事件，执行 `replay_dead()` 后用可观测 sender 运行 relay，确认状态为 `sent` 且 Celery `task_id` 等于稳定 `event_id`，最后删除演练数据。该命令验证数据库 outbox 逻辑，不会调用真实 LLM。

1. 让一个任务进入 `awaiting_review`，记录其 `thread_id`，重启 worker。
2. 使用相同 `thread_id` 调用人工审核接口；`resume_human_review()` 从 PostgresSaver 恢复，不重新生成已完成节点。
3. 将 `task_outbox.status` 置为 `dead` 的演练事件记录其 `id`，执行：

```powershell
docker compose -f deploy/docker-compose.yml run --rm backend `
  python scripts/replay_outbox.py <task_outbox.id>
```

4. 运行 `relay_task_outbox`。relay 使用 `event_id` 作为 Celery `task_id`，重复投递安全；调度器按 `(task_id, item_index)` 查重，不重复创建 item。

## 验收证据

- `psql -lqt` 能看到两个数据库。
- 预检输出单一 `head`，迁移完成后 `alembic current` 等于该 head。
- 恢复库可查询 `question_template`、`generation_task`、`trace_log`、`task_outbox`，源库数据不变。
- checkpoint 恢复后 trace 出现 `workflow/resume`，同一 item 不产生第二条成功内容；最小演练图的跨连接恢复由 `recovery_drill.py` 验证。
- dead outbox 重放后状态为 `pending -> sent`，`attempts` 和原错误保留。

已在 Docker Compose 基础设施环境完成 PostgreSQL/Redis 健康检查、Langfuse 数据库初始化、迁移预检、`alembic upgrade head`、`alembic current` 以及 `pg_dump` 到独立恢复库的验证。真实 LangGraph PostgresSaver checkpoint 与 outbox 脚本演练需按第 4.1/4.2 节执行后，将命令输出补入优化记录；它们不等同于真实 LLM worker kill/restart 业务链路验收。
