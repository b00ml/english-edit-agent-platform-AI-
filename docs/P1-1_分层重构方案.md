## 三层架构设计

### Layer 1: API（routes.py 瘦身）
**职责**：请求解析、认证鉴权、响应序列化、异常捕获
**禁止**：直接访问数据库、复杂业务逻辑、调用 LLM

### Layer 2: Service（新增）
**职责**：业务逻辑、工作流编排、事务边界、权限校验
**依赖**：Repository（数据）+ Engine（LLM）+ Worker（异步任务）

### Layer 3: Repository（新增）
**职责**：数据访问、查询构建、ORM 操作
**禁止**：业务逻辑、事务管理（由 Service 控制）

- routes.py 仅保留：参数解析、依赖注入、Service 调用、响应格式化
- 目标行数：< 500 行（从 1385 降至 500）

## 重构原则
1. **向后兼容**：URL、请求/响应格式不变
2. **渐进式**：按领域逐个迁移，每个领域独立测试
3. **测试先行**：Service 层必须有单元测试
4. **事务边界**：Service 层控制事务，Repository 不自动提交

## 风险控制
- 每完成一个领域，运行全量测试验证
- 保留原 routes.py 为 routes_legacy.py 备份
- 如发现回归问题，可快速回滚单个领域
